## 1. Крупные функциональные блоки

### 1.1. Переработка профиля Артиста / Коллектива (самое крупное)
- Объединение **Артист + Группа** в единую сущность; статусы артиста (черновик / на модерации / отклонён / верифицирован) с **одностадийной верификацией** (код при создании, проверка условий, отзыв заявки, проверка дублей названия).
- **Статус активности** (Действующий / Неактивный / Архивный / Распался) с авто-переводом участников «Действующий→Бывший» и обратным восстановлением при реактивации.
- **Участники:** добавление / подтверждение / отклонение, роли из каталога ролей, статус участия (действующий / бывший), **инвайт-ссылки** с ролями + консьюм при регистрации.
- **Админ-блок:** владелец + админы, смена владельца, управление составом.
- **Релизы и клипы:** CRUD, слайдеры, формы с авто-подтягиванием метаданных, участники с подтверждением, страницы с внешними ссылками.
- Избранное (звезда) вместо «Подписаться»; кнопки правки/шэра под обложкой; ретайр старых `/groups` (редирект на Артиста).
- Уведомления артист/релиз/клип через централизованный `notify()` + web-push.

### 1.2. Moooza Pro
- Платный **Pro по времени**; донаты через **CloudTips** (встроенная форма / top-level открытие); донат-коды + админ-верификация.
- Авто-начисление Pro-месяцев за **рефералов** (каждые 10 регистраций); реферальные ссылки (одноразовые).
- **Pro-гейтинг лимитов:** портфолио / био / GIF; пресеты фильтров ленты (free 1 / Pro безлимит, серверное хранение).
- Экран «Moooza Pro» + карточка входа в профиле.

### 1.3. Переработка Каталога (вкладки Услуги / Артисты / Люди)
- Вкладки по ТЗ; структурный пост **«Услуга»** в Потоке (Post→UserService), шаблоны «Написать» + контактный эндпоинт, диалоги публикации/обновления.
- **Черновики услуг** + автосейв при случайном закрытии; лимит 50 символов на название (сервер).
- Переиспользуемый **AuthGateModal** + `useAuthGate` (гейт действий для гостей).

### 1.4. Профиль (фичи + правки тестировщика)
- **Каталог городов** (выбор только из списка, ~157 городов РФ) + валидация.
- Лимиты ФИО/ник (Имя≤20 / Фам≤30 / Ник≤20), **уникальность ника** (case/ё-нечувств., все пути + индекс).
- Фильтры профессии — **свёрнутые аккордеоны** + редактируемые **features**; фикс **сброса сохранённых фильтров**; **прогресс-бар** заполненности.
- **Обрезка аватара/баннера** перед загрузкой (react-easy-crop).

### 1.5. Поиск
- **ё/е-нечувствительный** поиск везде (Postgres generated `*Norm` колонки); старт поиска **с 1 символа**.

### 1.6. Соцсети и контакты
- Только **разрешённые платформы** (блок при вставке запрещённых), удалён Instagram; **3-уровневая видимость контактов** (Все / Зарегистрированные / Друзья).

### 1.7. Юридические документы
- Подвал лендинга: кнопка **«Документы»** (поп-ап со всеми 8 документами) + **реквизиты ООО «МУЗА»** *(уже на PROD)*.
- Свежие `/terms` и `/privacy` из единого источника *(уже на PROD)*.
- **Согласие на публичное распространение ПДн** — однократно при первом публичном действии (услуга / портфолио / контакты «Все»), фиксируется на сервере.

### 1.8. Прочее
- **Сделки временно скрыты** (создание + вкладка «Деловые») — флаг `DEALS_ENABLED=false`. ⚠️ см. п.4.
- SEO (robots/sitemap/canonical/JSON-LD/тайтлы); убраны счётчики контента и счётчики-чипы вкладок; убраны in-dev типы постов из создания.

## 4. Критичные пункты миграции (ОБЯЗАТЕЛЬНО проверить)

1. **Бэкап боевой БД PROD ДО миграции** — обязательно (откат).
2. **Каталог городов City — пустой после миграции.** Сид городов — это **TS-сид** (`prisma/seeds/cities.ts`), а НЕ миграция → его нужно **запустить вручную** на PROD (иначе CityPicker пустой). Роли (`seed_roles`) — наоборот, в миграции, применятся сами.
3. **Флаг `DEALS_ENABLED=false` скроет сделки и вкладку «Деловые» на PROD.** На PROD сейчас сделки живые. **Решить:** оставить скрытыми на проде или включить (`true`) перед релизом.
4. **Артист-переработка меняет модель Артист/Группа** — на PROD есть живые группы/артисты. Проверить, что миграция корректно переносит существующие данные (схема — миграцией; данные — проверить вручную/скриптом перед боем).
5. **Telegram-уведомления** — на PROD `api.telegram.org` заблокирован из РФ по IPv4; нужен рабочий путь (релей/`TELEGRAM_API_BASE`), иначе уведомления молча не уйдут.
6. **Согласие на публичное распространение** — существующие PROD-юзеры будут без согласия; гейт всплывёт при следующем публичном действии (ожидаемо).
7. **Новые env-переменные** (CloudTips, mailer, telegram base и пр.) — добавить в `docker-compose` PROD.

## 5. Рекомендованный порядок выката
1. Снять бэкап БД PROD.
2. Merge `dev → master`, push.
3. На PROD: `git pull` → `prisma migrate deploy` (НЕ db push) → собрать web+api.
4. **Запустить сид городов** (`npx tsx prisma/seeds/cities.ts`).
5. Решить вопрос с `DEALS_ENABLED` и Telegram-релеем.
6. Прогнать smoke-тест: профиль, артист, поиск, каталог, документы, согласие.
